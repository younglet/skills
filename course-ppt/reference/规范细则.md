# 课件 PPT 生成规范（细则）

> 适用于"教材式"课程 PPT（如 MicroPython MP1/MP2/MP3）。
> 核心原则：**一页只讲一件事；关键概念先有"知识点介绍页"，再做原理/特点/应用分析；代码紧跟它对应的课堂环节。**

---

## 一、目录结构（推荐）

```
<项目根>/
├── 模板.pptx            # 16:9 母版；版式名：1_自定义版式（封面）、3_自定义版式（内容）
├── build_ppt.py         # 把 PPT 源 md 编译成 .pptx
├── inject_codes.py      # （首次）把 source_codes 的代码贴进 PPT 源
├── place_codes.py       # 把代码页贴到对应环节旁边（含 20 行分页、去顶部注释）
├── <课程>/
│   ├── PPTs/            # 该课程课件：MPx_XX_*.md（源）+ MPx_PPT.pptx（成品）
│   ├── lesson_plans/    # 教案（内容底稿，权威文本）
│   └── source_codes/    # 每讲配套代码（PPT 里贴的就是这些）
```

- **PPT 源** 是唯一需要手改的文件；**`.pptx` 是生成物**，不要直接改。
- **代码不手写进 PPT 源**，由 `inject_codes.py` + `place_codes.py` 自动贴入。

---

## 二、硬性规范

1. **一页只讲一件事**；不设纯流程页（"本节课分几个环节"之类）。
2. **关键概念先有"知识点介绍页"**，再讲原理/特点/应用。
3. **不要 emoji**（生成时文本与代码统一切除）。
4. **不要面向老师的元叙述**：如"本节一共几个脚本""下面逐个讲解""上课前先……"——课件只写给学生看的内容。
5. 页面文字**不以标点起句**（生成时已设悬挂标点）。
6. 内容用**表格 + 小标题**呈现；正文框统一微软雅黑、无填充无边框。
7. 只有**封面大标题是白色**，内容页标题用模板原色。
8. **动画只加**"解答性内容 / 页内第二个小环节"，其余静态。

## 三、PPT 源写法

### 分页

```markdown
### 第 3 页 · 知识点：什么是 H 桥
- 答：正文……
- 表：小标题

| 列1 | 列2 |
| --- | --- |
| a | b |

```python
print('代码块渲染成 Consolas 等宽文本框')
```
```

页号必须连续；生成脚本按顺序出片。

### 行标记

| 标记 | 渲染效果 |
| --- | --- |
| `问：` | 提问（加粗、静态，不参与动画） |
| `答：` | 正文（显示时去掉"答："前缀） |
| `图：` | 渲染成"【图片占位】应插入图片：<描述>" |
| `注意：` / `练习：` | 原样保留为小标签 |
| `### 小标题` | 页内子标题（蓝色加粗） |
| `\| … \|` 表格 | 转成 PPT 真表格 |
| ` ``` ` 代码块 | Consolas 等宽文本框，自动 9~12pt |

## 四、每讲固定结构

```
封面
复习：上节要点回顾            ← 问答成对：问 → 答（紧贴） → 间隔行
代码回顾：<上一讲核心脚本>
课程引入
知识点 …            ← 每个环节后面紧跟它自己那部分代码
（模块页：介绍+硬件引脚 / 初始化参数 / 核心属性或方法 / 使用示例）
编程任务 …          ← 同样紧跟对应代码
小结与拓展
```

- **代码贴着任务走**：不集中在末尾，不做"附录"。
- **没有单独的"代码清单/代码列表"页。**

---

## 五、模块页的四页格式

参考 `MP1课件.pptx`：

1. `### 模块介绍` + `### 硬件引脚说明`（表格）
2. `### 初始化参数`（表格）+ `### 导入和实例创建`（代码）
3. `### 核心属性或方法`（表格）
4. `### 使用示例`（代码）

函数式模块（如 `requests`）没有构造参数，可用 `### 常用函数` 代替。

---

## 六、代码排版规范（重点）

1. **每页代码最多 20 行**。超出自动拆成多页，页标题带 `（1/2）（2/2）`。
2. **分页以逻辑为准，兼顾均衡**：
   - 优先断在**逻辑边界**：空行、`def`/`class`/`@`/注释分段处；
   - 在逻辑清楚的前提下，**尽量让各页行数接近**（例如 22 行 → 11/11，25 行 → 13/12），
     而不是硬切 20/5；
   - **逻辑优先于均衡**：宁可 14/8，也不要为了平均把函数从中间劈开。
3. **顶部注释头不带进课件**：文件开头的 `# 文件名:` / `# 功能:` / `# 说明:` 等整块注释与空行一律剔除，从第一行真正代码开始。
4. **代码紧跟对应环节**：由 `place_codes.py` 顶部的 `M` 字典决定"哪个脚本贴到哪一页后面"（锚点子串 → 脚本列表）。
5. **代码回顾页**放在"复习"页之后，内容是上一讲的核心脚本。
6. **不贴厂商/库文件**（`nova-style*`、`novajs*`、`nova-chart.min*`、`matrix-board.js` 等）。
7. 渲染时代码中的 emoji 会被去掉；字号按行数自动取 12/11/10pt。
8. **步骤代码标题不写"第几步"**：标题取脚本头注释的"功能描述"；**对应环节与源文件名放在页脚**（微软雅黑 10pt 灰色）。
9. **与前面某一步基本相同（相似度 ≥85% 且改动 ≤6 行）的代码不再重复贴**，改为一页说明"本步代码与《xx》基本相同（仅新增/修改 N 行），不再重复展示"。

## 七、工具与流程

在项目根目录执行：

```bash
# 1) 生成两个 PPT（读 <课程>/PPTs/MPx_*.md，输出 <课程>/PPTs/MPx_PPT.pptx）
python build_ppt.py

# 2) 首次给某讲补"复习 + 代码回顾 + 任务代码"页（已注入过会自动跳过）
python inject_codes.py MP2      # 或 MP3

# 3) 把代码页贴到对应环节旁边（会先清掉旧的代码页/代码回顾，再按 20 行重插）
python place_codes.py MP2       # 或 MP3；不带参数则两门都跑

# 4) 汇总配图需求（教案 + PPT 里的“图：……”）→ 每讲一份带 描述/关键词/功能/出处 的 MD
python extract_image_needs.py   # 默认输出到 桌面/images/（需先 pip install jieba）

# 5) 把生成好的图片绑定回 PPT 源（按“出处”精确匹配，幂等）
python attach_images.py

# 6) 按教案的「复习环节」重建复习页（问答成对、答案精简到一行）
python rebuild_review.py
```

- 生成时若 `.pptx` **正开在 PowerPoint 里**会被锁定，脚本会改存为 `MPx_PPT_fixed.pptx`；关掉后覆盖回去即可。
- 顺序：改源 md → （如需）`place_codes.py` 重排代码 → `build_ppt.py` 生成。

## 八、改内容时改哪里

| 想改什么 | 改这里 |
| --- | --- |
| 讲稿文字、顺序、概念页 | `<课程>/PPTs/MPx_XX_*.md` |
| 贴出来的代码 | `<课程>/source_codes/…`，再跑 `place_codes.py` |
| 代码贴在哪个环节 | `place_codes.py` 顶部 `M` 字典 |
| 重复代码的判定阈值 | `place_codes.py` 的 `SIM` / `ADD_MAX` |
| 配图与 PPT 的对应 | 各页的 `图：images:<相对路径> \| <描述>`；根目录由 `COURSE_IMG_ROOT` 指定 |
| 代码回顾选哪个脚本 | `inject_codes.py` 顶部 `REVIEW` 字典 |
| 字号 / 排版 / 动画 / 表格样式 | `build_ppt.py` |
| 母版版式 | `模板.pptx` |
| 不贴进 PPT 的讲法底稿 | `<课程>/lesson_plans/` |
